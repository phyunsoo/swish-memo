# 기술 선택 기록

## 2026-10-08 — 첫 iPhone 버전

- **앱 UI: React Native + Expo + TypeScript.** 화면과 일반 메모 흐름을 빠르게 다듬을 수 있고, Expo 개발 빌드에서 Swift 확장을 함께 사용할 수 있다.
- **기기 저장: SQLite (`expo-sqlite`).** 메모는 계정이나 서버 없이 오프라인에서 바로 열고 수정해야 한다. 메모·폴더·상태를 관계형 테이블로 관리하고, 위젯도 같은 로컬 DB를 읽고 쓴다. PostgreSQL 서버는 두지 않는다.
- **iCloud: Swift + CloudKit private database.** 사용자 본인의 Apple 계정 안에서 동기화하므로 앱 자체 로그인이나 별도 백엔드가 필요 없다. 앱이 오프라인일 때 먼저 SQLite에 기록한 뒤 연결이 복구되면 동기화한다.
- **홈 화면 위젯: Swift + WidgetKit + App Intents.** 위젯에서 앱을 열지 않고 투두를 완료해야 하므로 iOS 위젯 타깃과 App Intent를 사용한다. 위젯과 앱은 App Group 컨테이너 안의 SQLite DB를 공유한다.
- **최소 지원 버전: iOS 17.** 위젯의 상호작용형 App Intent와 앱 확장 구성을 첫 버전 범위로 묶기 위해 설정했다.
- **충돌 처리: 양쪽 메모를 보존.** 동기화 기준 시각보다 양쪽 데이터가 모두 새로우면 기기 메모를 충돌 사본으로 남기고 CloudKit 버전을 적용한다.

### 확인 범위

Expo lint, TypeScript 타입 검사, iOS Simulator용 앱 및 WidgetKit 타깃 빌드, 메모 작성 화면 진입까지 확인했다. 현재 Simulator 빌드는 Xcode의 ad hoc 서명이라 App Group·iCloud entitlement가 포함되지 않는다. CloudKit 동기화와 홈 화면 위젯의 공유 DB 동작은 Apple 개발 서명 및 실제 기기 설정 후 검증해야 한다.

## 2026-10-11 — 투두 위젯 공유 저장소

- **홈 화면 크기:** 소형·중형·대형을 지원한다. 화면 높이와 Dynamic Type에 맞춰 항목 수를 줄이고, 본문은 한 줄 말줄임으로 표시한다. 나머지는 앱의 투두리스트로 이동해 확인한다.
- **네이티브 타깃 생성:** `my-app/plugins/with-todo-widget.js`가 WidgetKit 타깃·App Group entitlement·Info.plist를 생성한다. 생성된 `ios/` 대신 `widgets/`와 로컬 모듈의 Swift 소스를 수정한다. 최소 지원 버전은 iOS 17이다.
- **데이터 이전:** iOS 메모 저장소는 App Group의 SQLite를 사용한다. 첫 실행에서 기존 앱 전용 SQLite의 스냅샷을 복사하며 원본 DB는 남긴다. 공유 저장소가 이미 있으면 다시 덮어쓰지 않는다. 화면 테마 설정은 기존 앱 전용 DB에 유지한다.
- **완료와 충돌:** App Intent가 트랜잭션 안에서 투두를 즉시 휴지통으로 이동하고 삭제 시각을 기록한다. 별도 완료 기록으로 앱의 늦은 저장이 항목을 되살리는 것을 막는다. 복구·재진입에는 새 투두 세대 식별자를 부여해 오래된 위젯의 체크가 복구 항목에 적용되지 않게 한다.
- **정렬:** 새 투두리스트는 최근 수정 순을 사용한다. 앱에서 순서를 바꾸면 수동 순서로 전환하고 위젯도 동일하게 표시한다. 이전 버전의 순서가 있으면 그대로 보존한다.
- **확인:** TypeScript·Expo lint, 앱·WidgetKit 시뮬레이터 빌드, Swift 저장소 테스트(최초 이전, 중복 완료, 오래된 저장, 복구, 별도 DB 연결, 동시 완료, 30일 만료)를 통과했다. iPhone 17 시뮬레이터에서 소·중·대 갤러리 미리보기, 앱 종료 상태의 위젯 체크와 공유 DB 기록, 앱 투두리스트로 이동, 앱 완료·휴지통 복구를 확인했다. App Group entitlement를 포함한 ad hoc 서명으로 검증했으며, 실제 기기의 개발 서명 검증은 별도로 필요하다. CloudKit 동기화는 현재 코드에 구현되어 있지 않으므로 이 위젯 구현의 완료 결과가 다른 기기로 동기화되지는 않는다.

## 2026-10-11 — 투두·위젯 리팩토링

- **저장 모듈 분리:** 공유 저장소·글자 수 계산·위젯 갱신은 `MemoStoreModule`이 담당하고, `LiquidGlassWheelModule`은 UI를 담당한다. 같은 로컬 패키지 안에서 Expo 모듈을 따로 등록한다. 네이티브 모듈 등록 변경으로 개발 앱 재빌드가 필요하다.
- **저장 대기열:** 진행 중인 저장은 유지하고, 연속으로 대기 중인 스냅샷은 최신 상태로 합친다. 앱 복귀 시 읽기는 저장 사이의 순서를 보존한다. 위젯 완료 병합은 내용 수정·복구 세대·수동 휴지통 정렬을 덮어쓰지 않는다.
- **완료 순서:** 앱과 위젯 모두 완료한 투두를 휴지통의 마지막 순서에 추가한다. 위젯 완료 기록에 순서를 함께 보관해 늦은 앱 저장에서도 유지한다. 기존 완료 기록 테이블은 트랜잭션 안에서 열을 추가한다.
- **화면 분리:** 메모 카드·텍스트 버튼은 별도 컴포넌트로, 투두 완료·메모 정렬은 `useNoteActions`로 분리했다. 작성 시간 위치·파란 완료 동그라미·드래그 복구 흐름을 유지한다.
- **검증:** TypeScript·Expo lint·저장 대기열 테스트·Swift 저장소 테스트와 앱·WidgetKit 시뮬레이터 빌드를 통과했다. 새 앱에서 공유 DB의 `sort_order` 열 이전, 작성 화면·투두 빈 화면·휴지통 카드 및 복구 버튼 제거 상태를 확인했다.

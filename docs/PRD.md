# swish — 제품 요구사항 문서(PRD)

- 문서 상태: 현재 구현 기준
- 기준일: 2026-10-18
- 기준 소스: `my-app/`의 화면, 상태 관리, 저장소, iOS 네이티브 모듈 및 위젯
- 주요 플랫폼: iOS. iPad와 넓은 창 레이아웃, Mac에서의 실행을 고려한 분기 포함
- 표시 언어: 한국어
- 제품 한 문장: 생각을 먼저 적어 카드로 쌓고, 길게 눌러 폴더로 끌어 정리하는 메모 앱

이 문서는 현재 코드에서 확인한 동작을 설명한다. 검증 시나리오는 실제 기기에서 확인할 항목이며, 이 문서의 개정만으로 실행 검증이 완료된 것은 아니다. 이전 기획과 달라도 현재 실행 경로의 동작을 기준으로 한다.

## 1. 제품 목표와 범위

swish는 제목이나 폴더를 먼저 정하지 않고 생각을 기록하는 앱이다. 작성한 내용을 완료 버튼으로 미분류 카드로 남기고 다음 내용을 이어서 작성한다. 정리가 필요하면 카드를 길게 누른 뒤 세로 폴더 메뉴로 끌어 저장하거나 이동한다.

주요 사용자는 빠르게 기록하고 나중에 분류하려는 사람이다. 핵심 경험은 다음과 같다.

1. 작성 화면에서 바로 입력하고 여러 미분류 메모를 모은다.
2. 입력 완료와 폴더 분류를 별개 동작으로 수행한다.
3. 폴더와 메모의 순서를 직접 정리한다.
4. 짧은 할 일을 앱과 홈 화면 위젯에서 확인하고 완료한다.
5. 기기에 데이터를 보존하고, 지원되는 iOS 빌드에서는 분류한 메모를 iCloud와 동기화한다.

포함 범위는 텍스트·사진 메모, 투두, 사용자 폴더, 드래그 이동, 수동 정렬, 현재 화면 검색, 휴지통, 표시 설정, 로컬 저장, iCloud 동기화 및 iOS 투두 위젯이다.

현재 제공하지 않는 기능은 인사이트 기본 폴더, 별도 임시저장 화면, 메모 고정·즐겨찾기·태그, 공동 편집·공유, 투두 알림·마감일·반복 일정·우선순위, 자체 계정 가입이다. 마크다운은 표시 옵션으로 제공하며 서식 편집 툴바는 제공하지 않는다.

Android·웹용 설정과 일부 대체 구현은 존재하지만, iOS 네이티브 메뉴·사진 처리·사용자 폴더 관리·CloudKit·위젯과 동등한 동작을 보장하는 범위로 간주하지 않는다.

## 2. 용어와 메모 상태

| 용어 | 현재 구현에서의 의미 |
| --- | --- |
| 작성 화면 | 미분류 메모 카드들과 새 메모 입력 영역을 함께 표시하는 기본 화면 |
| 작성 중 입력 | 아직 카드로 확정하지 않은 글·사진. 기존 카드 목록과 별도로 기기에 보존 |
| 미분류 메모 | 완료한 카드 중 폴더를 배정하지 않은 메모. 상태는 `draft` |
| 저장된 메모 | 투두리스트 또는 사용자 폴더에 속한 메모. 상태는 `saved` |
| 휴지통 메모 | 삭제하거나 완료 처리한 메모. 상태는 `trash` |
| 투두 메모 | 투두리스트에 저장된 텍스트 전용 할 일 하나 |
| 폴더 메뉴 | 카드를 길게 눌러 드래그할 때 나타나는 세로 이동 대상 목록 |

메모에는 본문, 사진, 표시 시각, 순서, 폴더, 상태, 삭제 시각, 동기화용 식별·변경 정보 등을 저장한다. 제목은 별도로 입력하지 않는다. 메모 고정 상태와 삭제된 폴더를 복구하는 데이터 구조는 없다.

## 3. 화면 구조

### 3.1 작성 화면과 상단 도구

- 앱은 작성 화면으로 시작한다. 저장소를 읽는 동안 로딩 화면을 표시한다.
- 좁은 화면에서는 미분류 카드 목록 뒤에 새 메모 입력 영역을 배치하고 입력에 자동 포커스를 요청한다.
- 새 입력은 여러 줄을 허용하며, 글 없이 사진만 있는 메모도 만들 수 있다.
- 글·사진이 모두 없을 때 사용자 설정 안내 문구를 표시한다.
- 좌측 상단은 폴더 아이콘 버튼이다. 우측에는 조건에 따라 완료 체크 버튼, 새 메모 버튼, 케밥 메뉴가 표시된다.
- 완료 체크 버튼은 내용이 있는 새 입력을 미분류 카드로 추가하고 입력 영역을 비운다. 글이 공백뿐이고 사진도 없으면 카드를 만들지 않는다.
- 새 메모 버튼은 작성 화면으로 전환한다. 기존 새 입력에 내용이 있으면 먼저 미분류 카드로 남기고 빈 입력 영역에 포커스를 요청한다.
- 여러 미분류 카드가 동시에 존재할 수 있다. 다음 메모를 쓰기 위해 폴더 이동이나 삭제를 완료할 필요는 없다.

### 3.2 카드 보기와 편집

- 카드에는 본문·사진, 시각, 편집 버튼을 표시한다. 투두 카드에는 완료 버튼도 표시한다.
- 시각은 메모의 `timestamp`를 한국어 날짜·시간 형식으로 표시한다. 본문 수정, 사진 변경, 폴더 드롭 등에서 갱신된다.
- 카드 높이는 내용에 따라 늘어나며, 테두리와 둥근 모서리를 사용한다.
- 읽기 상태에서는 일반 텍스트 선택이 가능하며, 설정에 따라 마크다운 또는 링크를 표시한다.
- 편집을 누르면 해당 카드 안에서 원문을 수정하고 버튼이 완료로 바뀐다. 완료하면 같은 메모를 갱신한다.
- 기존 카드의 본문 편집은 별도 편집 상태로 유지하다가 완료 또는 화면 전환 등의 저장 경로에서 반영한다. 입력 중 매 글자가 원본 메모에 즉시 저장되는 것으로 규정하지 않는다.
- 카드 편집 중이나 검색 중에는 폴더 이동 드래그를 비활성화한다.

### 3.3 폴더 서랍

서랍의 항목 순서는 작성 화면, 투두리스트, 휴지통, 구분선, 사용자 폴더들이다. 각 항목에는 해당 메모 수를 표시하며, 상단에는 폴더 추가 버튼을 둔다.

- 폴더 아이콘 버튼으로 열고 바깥 영역을 누르면 닫는다.
- 좁은 화면에서는 가로 스와이프로도 열고 닫을 수 있다.
- 사용자 폴더는 드래그로 순서를 바꿀 수 있다.
- 인사이트·임시저장 항목과 하단 고정 검색 바는 없다. 검색은 현재 화면의 케밥 메뉴에서 연다.

### 3.4 넓은 화면

- 창 너비 840 이상에서는 메모 목록과 상세 영역을 나누어 표시한다.
- 목록에는 첫 줄 기반 제목, 나머지 본문 미리보기, 날짜, 사진 개수를 표시한다. 본문이 없으면 사진 메모 또는 빈 메모로 표시한다.
- 목록에서 메모를 선택하면 상세 영역에 카드를 표시한다. 작성 화면에서 선택한 카드가 없으면 새 입력 영역을 표시한다.
- 창 너비 1180 이상에서는 폴더 사이드바를 고정한다.
- 넓은 화면에서는 새 입력에 자동 포커스를 요청하지 않는다. 사진 첨부가 가능한 경우 상단에 별도 첨부 버튼도 표시한다.
- Mac 실행 환경에서는 이미지 드롭과 사진 선택을 위한 별도 처리 경로를 사용한다.

## 4. 케밥 메뉴와 설정

### 4.1 화면별 메뉴

| 화면 | 메뉴 항목 |
| --- | --- |
| 작성 화면 | 설정, 검색, 순서 바꾸기, 사진 첨부, 모두 삭제 |
| 투두리스트 | 설정, 검색, 순서 바꾸기 |
| 사용자 폴더 | 설정, 검색, 순서 바꾸기, 폴더 이름 변경, 폴더 색상 편집, 폴더 아이콘 편집, 폴더 삭제 |
| 휴지통 | 설정, 검색, 순서 바꾸기, 휴지통 비우기 |

사진 첨부 항목은 현재 대상이나 작업 상태에 따라 비활성화한다. 고정·고정 해제와 개별 메모 삭제 항목은 없다. 개별 메모는 드래그로 휴지통에 옮긴다. 순서 변경 중에는 상단 완료 버튼으로 정렬을 마친다.

작성 화면의 모두 삭제는 확인 대화상자를 거쳐 화면의 미분류 카드, 열어 둔 관련 메모와 내용이 있는 새 입력을 휴지통으로 옮기고 입력 영역을 비운다.

### 4.2 설정

- 화면 모드: 라이트·다크를 직접 선택하고 기기에 저장한다. 기본값은 라이트다.
- 플레이스홀더 텍스트: 새 입력에 표시할 안내 문구를 편집한다.
- 텍스트 크기: 12·16·20·24·28pt 중 선택한다. 기본값은 20pt다.
- 마크다운: 편집하지 않는 카드에서 마크다운을 렌더링한다. 기본값은 꺼짐이다.
- 하이퍼링크: 링크 표시·동작을 활성화한다. 기본값은 꺼짐이다.
- 정보: iCloud 상태, 앱 버전, 개인정보 처리방침의 준비 중 표시를 제공한다.
- iCloud 상태에는 계정 사용 가능, 로그인 필요, 동기화 중, 동기화됨, 오류 등의 상태를 표시한다. 별도 동기화 켜기·끄기 스위치는 없다.

## 5. 폴더와 메모 규칙

### 5.1 기본 폴더와 사용자 폴더

- 기본 폴더는 삭제할 수 없는 투두리스트 하나다.
- 폴더 추가 경로는 기본 폴더를 포함해 최대 12개로 제한한다. 따라서 사용자 폴더는 최대 11개다.
- 작성 화면과 휴지통은 이 제한에 포함하지 않는다.
- 사용자 폴더 생성 시 이름의 앞뒤 공백을 제거하고 빈 이름을 받지 않는다. 대소문자를 구분하지 않는 중복 이름도 거부한다. 이름 변경에도 같은 규칙을 적용한다.
- 사용자 폴더는 이름·아이콘·색상을 변경할 수 있다. 설정한 모양은 서랍, 이동 메뉴와 폴더 화면에 반영한다.
- 폴더 삭제는 확인 후 실행한다. 폴더 자체는 제거하고 그 안의 저장된 메모를 폴더 미지정 상태로 휴지통에 옮긴다.
- 삭제한 폴더를 휴지통에 보관하거나 폴더째 복구하는 기능은 없다.

### 5.2 일반 메모와 사진

- 한 저장된 메모는 하나의 폴더에 속한다. 미분류 메모에는 폴더가 없다.
- 글과 사진을 함께 담거나 사진만 담을 수 있다.
- 사진은 작성 화면 메뉴, 키보드 도구 또는 넓은 화면의 첨부 버튼으로 추가한다. 기존 카드의 사진은 편집 중 제거할 수 있다.
- 투두 메모에는 사진을 첨부하지 않는다.
- 첨부 처리 도중 대상 메모나 새 입력 세션이 달라지면 이전 작업 결과를 새 대상에 붙이지 않는다. 실패 시 안내하고 기존 내용을 유지한다.
- 기존 메모의 편집·이동은 같은 메모를 갱신하며 복제본을 만들지 않는다.

### 5.3 투두 메모

- 투두 메모 하나가 할 일 하나다. 공백뿐인 내용은 허용하지 않는다.
- 사용자가 보는 문자 기준 최대 30자이며 줄바꿈과 사진을 허용하지 않는다.
- 일반 메모를 투두리스트에 드롭할 때 제한을 검사한다. 위반하면 이유를 알리고 원래 메모를 유지한다. 드래그 중 미리 저장 불가 표시를 하는 기능은 없다.
- 투두 본문 편집의 완료 단계에서도 길이와 줄바꿈을 검사한다.
- 앱의 투두 완료 버튼 또는 위젯 체크 버튼을 누르면 즉시 휴지통으로 옮긴다.
- 휴지통에서 투두리스트로 다시 옮기면 미완료 항목으로 돌아온다. 이때도 투두 형식 제한을 적용한다.

### 5.4 표시 순서

- 작성 화면·사용자 폴더·휴지통은 저장된 순서 값을 기준으로 표시한다. 순서 값이 없는 기존 데이터는 메모 시각을 대체 기준으로 사용한다.
- 새 카드와 다른 위치에서 이동한 메모는 해당 위치의 뒤에 추가한다.
- 케밥 메뉴의 순서 바꾸기에 들어가 핸들을 드래그하면 메모 순서를 조정한다.
- 투두리스트의 초기 정렬은 최근 수정 순이다. 투두 순서를 직접 바꾸면 수동 정렬로 전환한다.
- 별도 고정 기능과 고정 메모 우선 배치는 없다.

## 6. 핵심 상호작용: 길게 누르기와 폴더 메뉴

현재 메모 이동 UI는 원형 휠이 아닌 세로 목록이다. 소스에 남아 있는 `folder-wheel.tsx`를 현재 화면의 이동 방식으로 해석하지 않는다.

### 6.1 열기와 선택

1. 읽기 상태의 메모 카드 또는 넓은 화면의 메모 항목을 약 400ms 길게 누른 뒤 드래그한다.
2. 원래 카드 대신 미리보기와 세로 폴더 메뉴를 표시하고 배경을 어둡게 한다.
3. 폴더는 현재 폴더 배열 순서대로 나열한다. 별도의 시계 방향 배치나 각도 구역은 사용하지 않는다.
4. 폴더 목록 아래 구분선 뒤에는 휴지통을 고정한다. 휴지통 화면에서는 이 항목이 영구삭제로 표시된다.
5. 화면에 맞춰 폴더 표시 영역을 줄이며 한 번에 최대 6개 폴더 행을 표시한다. 나머지는 위·아래 가장자리 자동 스크롤로 접근한다.
6. 가장자리에서 약 300ms 머무르면 스크롤을 시작한다. 자동 스크롤 중에는 이동 대상을 선택하지 않는다.
7. 행 위에 손가락이 들어오면 배경으로 선택 상태를 표시한다. 드래그 시작과 다른 유효 대상으로 진입할 때 햅틱을 사용한다.

### 6.2 드롭 결과

| 드롭 위치 | 결과 |
| --- | --- |
| 투두리스트 또는 사용자 폴더 | 같은 메모를 해당 폴더의 저장된 메모로 이동 |
| 현재 폴더 | 같은 폴더에 유지하며 시각·배치 순서를 갱신 |
| 일반 화면의 휴지통 | 메모를 휴지통으로 이동 |
| 휴지통 화면의 폴더 | 선택한 폴더로 복구 |
| 휴지통 화면의 영구삭제 | 해당 메모를 즉시 제거 |
| 대상 밖·행 사이·스크롤 중 또는 제스처 취소 | 이동하지 않고 원래 카드 표시로 복귀 |

- 미분류 카드와 저장된 카드에 같은 폴더 메뉴를 사용한다. 임시저장 대상으로 드롭하는 항목은 없다.
- 새 입력 영역 자체는 이동 대상 카드가 아니다. 먼저 완료하거나 새 메모 버튼으로 카드로 만든 뒤 이동한다.
- 드롭 후 현재 화면에 머문다. 항상 빈 작성 화면으로 전환하는 규칙은 없다.
- 휴지통에서 복구할 때 원래 폴더로 자동 복원하지 않는다. 사용자가 선택한 폴더로 이동한다.
- 개별 영구삭제 드롭에는 추가 확인 대화상자가 없다. 휴지통 전체 비우기는 확인 후 실행한다.

## 7. 저장과 재실행

### 7.1 작성 중 입력과 미분류 카드

- 새 입력의 글·사진은 상태 변경에 따라 로컬 저장한다. 완료 시 하나의 미분류 카드로 옮기고 새 입력을 비운다.
- 앱을 다시 실행하면 저장된 새 입력과 미분류 카드 목록을 불러온다.
- 가장 최근 미분류 메모를 입력 영역으로 자동 옮겨 편집하는 방식은 아니다.
- 새 입력·미분류 카드는 기기 보존 대상이며 iCloud 동기화 대상은 아니다.
- 기존 카드의 본문 편집 중 강제 종료까지 모든 글자가 보존된다고 보장하지 않는다. 카드 편집의 저장 시점은 3.2절을 따른다.

### 7.2 로컬 저장과 오류

- 기본 로컬 저장소는 SQLite다. 지원되는 iOS 빌드에서는 앱과 위젯이 App Group 공유 저장소를 사용한다.
- 로컬 저장과 클라우드 병합 결과 반영은 직렬 처리하며, 네트워크 대기로 로컬 저장을 막지 않는다.
- 앱이 활성 상태로 돌아오면 저장소를 다시 읽어 위젯에서 처리한 결과 등을 반영한다.
- 최초 데이터 읽기에 실패하면 안내하고 저장을 중지한다. 기존 데이터를 빈 상태로 덮어쓰지 않도록 한다.
- 이후 저장 실패는 로그로 기록한다. 저장 실패 전반에 대한 별도 사용자 복구 화면은 구현되어 있지 않다.

## 8. 검색과 휴지통

### 8.1 검색

- 검색 범위는 현재 화면에 표시되는 카드다. 전체 폴더를 한꺼번에 검색하지 않는다.
- 작성 화면에서는 미분류 카드와 해당 화면에서 열어 둔 관련 카드를 대상으로 한다. 카드로 만들기 전 새 입력 영역은 검색 대상이 아니다.
- 휴지통에서도 검색할 수 있다.
- 본문에서 입력 문자열과 일치하는 부분을 찾으며 영문 대소문자를 구분한다. 정규식 검색은 제공하지 않는다.
- 일치 부분을 강조하고 이전·다음 버튼으로 이동한다. 결과 수는 메모 수가 아니라 본문의 일치 횟수다.
- 검색 중인 기존 카드에는 편집 중 텍스트를 검색에 반영한다. 검색을 닫으면 일반 화면으로 돌아간다.

### 8.2 휴지통

- 삭제한 메모와 완료한 투두를 함께 보관한다. 삭제된 폴더 목록은 없다.
- 개별 메모는 길게 눌러 원하는 폴더로 드래그해 복구하거나 영구삭제한다.
- 휴지통 비우기는 확인 후 모든 휴지통 메모를 영구 삭제한다.
- iOS 공유 저장소는 저장 시 삭제 시각으로부터 30일 이상 지난 휴지통 메모를 정리한다. 정확히 30일이 되는 순간에 별도 백그라운드 작업이 실행되는 방식은 아니다.
- 공유 저장소가 없는 대체 저장 경로에는 같은 30일 정리 로직이 없다.
- 삭제 시각은 내부에 저장하지만 현재 카드에는 별도 삭제일·영구 삭제 예정일 표시가 없다.

## 9. 홈 화면 투두 위젯

- iOS WidgetKit 위젯이며 작은·중간·큰 크기를 지원한다.
- 미완료 투두의 개수와 목록을 표시한다. 항목은 한 줄로 제한하고 긴 문장은 말줄임한다.
- 표시 가능한 행 수는 위젯 높이와 글씨 크기에 따라 정한다. 남는 항목은 더 보기 링크로 안내한다.
- 위젯의 체크 버튼은 앱을 열지 않는 App Intent로 공유 저장소의 메모를 휴지통으로 옮기고 위젯 갱신을 요청한다.
- 제목·항목 텍스트·더 보기 링크는 앱의 투두리스트 화면을 연다.
- 기본 표시 순서는 최근 수정 순이다. 앱에서 수동 정렬하면 위젯도 해당 순서를 사용한다. 위젯 안에서 직접 드래그 정렬하는 기능은 없다.
- 빈 목록에는 할 일이 없음을, 저장소 접근 실패 시에는 앱을 열어 확인하라는 안내를 표시한다.
- 위젯 완료와 앱 저장이 겹쳐도 완료가 덮어써지지 않도록 처리하며, 복구한 투두에 과거 완료 요청이 다시 적용되지 않도록 구분한다.
- 위젯 완료는 오프라인에서도 공유 저장소에 반영한다. 클라우드 반영은 이후 앱의 동기화 경로를 따른다.

## 10. iCloud 동기화

- 지원되는 iOS 네이티브 빌드에서 같은 Apple 계정의 CloudKit 비공개 데이터베이스를 사용한다. 앱 자체 로그인은 요구하지 않는다.
- 동기화 대상은 폴더, 저장된 메모·휴지통 메모와 첨부 사진, 삭제 기록이다. 메모 순서 및 폴더 이름·색상·아이콘 등의 정보도 해당 데이터에 포함한다.
- 작성 중 입력, 미분류 카드와 화면 표시 설정은 기기별 로컬 데이터로 취급한다.
- 데이터 읽기·저장 이후 동기화를 요청하며, 실패하면 대기 시간을 늘려 재시도한다. iCloud를 사용할 수 없어도 로컬 사용을 계속한다.
- 상태는 설정 화면에서 확인한다. 네이티브 동기화 모듈이 없는 빌드에서는 앱 업데이트 필요로 표시한다.
- 같은 데이터가 충돌하면 수정 시각을 우선하고, 같은 시각은 변경 식별자를 비교해 하나를 선택한다. 양쪽 본문을 보존하는 충돌 사본이나 병합 편집 화면은 없다.
- 영구 삭제는 삭제 기록을 남겨 동기화하고, 오래된 클라우드 데이터가 다시 나타나는 것을 방지한다.
- 다중 기기·오프라인·사진 동기화의 실제 성공 여부는 별도 기기 검증이 필요하다.

## 11. 품질과 현재 제약

- iOS 네이티브 메뉴·컨트롤과 유리 효과를 지원 환경에 맞게 사용하며, 라이트·다크 화면을 제공한다.
- 주요 애니메이션은 시스템 동작 줄이기 설정을 따르는 경로를 사용한다.
- 화면 여백, 키보드 높이와 창 크기를 고려해 입력·목록·이동 메뉴를 배치한다.
- 접근성 레이블과 힌트는 일부 주요 버튼·메모·위젯에 제공한다.
- 폴더 이동 메뉴는 접근성 탐색에서 숨겨진 드래그 오버레이다. VoiceOver용 별도 폴더 선택 대안은 현재 구현되어 있지 않다.
- 개인정보 처리방침은 설정에 준비 중으로 표시된다.
- iPad·Mac용 화면 분기는 코드에 존재하지만, 실제 기기 검증 완료나 모든 플랫폼의 기능 동등성을 뜻하지 않는다.

## 12. 검증 시나리오

다음은 현재 코드 동작을 기준으로 한 수동 검증 항목이며, 모두 실행해야 하는 확인 목록이다.

1. 첫 실행에서 작성 화면이 열리고 좁은 화면의 새 입력에 포커스가 잡힌다.
2. 글을 쓰고 완료하면 미분류 카드가 추가되며 입력 영역이 비워진다. 여러 카드를 연속으로 만들 수 있다.
3. 내용이 있는 상태에서 새 메모를 누르면 기존 입력이 카드로 남고 새 입력을 시작한다. 빈 입력은 카드를 만들지 않는다.
4. 사진만 있는 메모를 만들고, 첨부 실패나 도중 화면 전환 시 다른 메모에 사진이 붙지 않는지 확인한다.
5. 카드를 편집·완료하면 같은 메모가 갱신된다. 투두의 잘못된 본문은 완료 단계에서 거부된다.
6. 카드를 약 400ms 길게 누른 뒤 끌면 원형 휠 대신 미리보기와 세로 폴더 목록이 나타난다.
7. 폴더가 1·6·12개일 때 메뉴가 화면 안에 놓이고, 가장자리 대기로 나머지 폴더까지 접근할 수 있다.
8. 폴더 행 선택 시 강조·햅틱이 나타난다. 대상 밖·행 사이·자동 스크롤 중 드롭과 제스처 취소는 이동하지 않는다.
9. 미분류 카드와 저장된 카드를 폴더로 옮기면 같은 메모가 이동한다. 드롭 후 현재 화면에 머문다.
10. 30자 초과·줄바꿈·사진이 있는 카드를 투두리스트에 드롭하면 거부되고 원본이 유지된다.
11. 폴더를 총 12개까지 생성하고 추가 생성을 제한한다. 빈 이름과 대소문자만 다른 중복 이름을 거부한다.
12. 사용자 폴더의 이름·색상·아이콘과 순서를 바꾸면 관련 화면에 반영된다.
13. 순서 바꾸기로 카드 순서를 변경한다. 투두 수동 순서가 위젯에서도 일치한다.
14. 현재 화면의 검색이 대소문자를 구분하고 모든 일치 위치를 강조한다. 휴지통에서도 검색되며 새 입력은 제외된다.
15. 개별 드래그 삭제와 작성 화면 모두 삭제가 올바른 메모를 휴지통으로 옮긴다.
16. 폴더 삭제 시 폴더는 제거되고 내부 메모만 휴지통으로 이동한다. 메모는 선택한 다른 폴더로 복구할 수 있다.
17. 휴지통의 개별 영구삭제와 확인 후 전체 비우기가 동작한다. iOS 공유 저장소 저장 시 30일 이상 된 메모가 제거된다.
18. 앱·위젯에서 각각 투두를 완료하면 휴지통으로 이동한다. 복구 후 과거 위젯 완료 요청으로 다시 삭제되지 않는다.
19. 앱 재실행 시 작성 중 입력과 미분류 카드들이 복원된다. 기존 카드 편집의 완료 전 강제 종료는 별도로 점검한다.
20. 오프라인에서 분류한 메모·사진·폴더를 변경한 뒤 앱 동기화를 통해 다른 기기에 반영되는지 확인한다. 미분류 카드·새 입력·표시 설정은 기기별로 유지된다.
21. 동일 메모의 동시 수정 시 수정 시각·변경 식별자 기준 선택을 확인한다. 충돌 사본 생성을 기대하지 않는다.
22. 라이트·다크, 글자 크기, 안내 문구, 마크다운·하이퍼링크 설정이 저장되고 표시에 반영된다.
23. 너비 840·1180 전후에서 목록·상세 분할과 고정 사이드바가 전환되고, Mac 환경의 사진 드롭이 동작한다.
24. 큰 글씨·작은 화면·키보드·동작 줄이기·VoiceOver 환경에서 사용성을 확인하고, 폴더 이동의 접근성 제약을 기록한다.
